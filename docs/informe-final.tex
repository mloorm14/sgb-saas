% choca con las comillas dobles literales que aparecen dentro de \texttt{}
% en prosa normal (ej. fragmentos de código citados inline en el cap. de
% Implementación) -- produce "Bad character code (-1)" en fuentes
% typewriter sin hyphenchar. Se desactiva ese shorthand global; no afecta
% el contenido de los entornos lstlisting (leen su texto de forma
% practicamente verbatim, sin pasar por los shorthands de babel).
% NOTA: "-" NO es un shorthand registrado por babel-spanish (intentar
% \shorthandoff{-} da error de compilacion: "not a shorthand") -- el bug
% de "Bad character code" con un guion suelto dentro de \texttt{} (ej.
% `docker compose down -v`) tiene otra causa (probablemente el propio
% guion como punto de hyphenation implicito en fuente sin hyphenchar) y
% se resuelve en el propio texto fuente, no aqui.
\shorthandoff{"}
